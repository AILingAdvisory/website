01 Executive Overview

"Black October" for AI Developer Platforms: Forensic Analysis of the LLMJacking Wave, Agent Swarm Credential Theft, and Enterprise Compute Exposure ________________ Publication Date: November 1, 2026 Classification: Enterprise Strategic Intelligence / Cloud Threat Intelligence & AI Infrastructure Security Primary Investigating Entities: Wiz Research, The Futurum Group, Cloud Security Alliance (CSA) Compromised Developer Platforms: Fireworks AI, Andromeda, Zeabur, Lightning AI, OpenCode, Railway, Warp, CommandCode, Northflank Key Attack Techniques: Environment Variable Scraping, Agent Swarm Reconnaissance, Multi-Region Bedrock LLMJacking, Darknet LLM Brokerage, Model Distillation Pipeline Harvesting Executive Summary ________________ In late October 2026, cloud security firm Wiz Research and tech advisory firm The Futurum Group released an alarming forensic investigation documenting what cybersecurity analysts have termed "Black October"—a wave of coordinated, highly automated cyber attacks targeting the developer platform layer of the artificial intelligence ecosystem. Over the course of thirty days, at least nine prominent AI development, deployment, and cloud workspace platforms disclosed critical security breaches: Fireworks AI (Oct 6), Andromeda (Oct 9), Zeabur (Oct 14), Lightning AI (Oct 15), OpenCode (Oct 16–17), Railway (Oct 20), Warp (Oct 23), CommandCode (Oct 28), and Northflank (Oct 30). The severity of the campaign resulted in the permanent operational shutdown of deployment platform Zeabur, which cited the breach as a primary contributing factor. While the initial intrusion vectors varied—spanning build infrastructure privilege escalations, third-party vendor dependencies, and legacy subsystem misconfigurations—the ultimate objective across all nine incidents was uniform: the automated exfiltration of stored environment variables containing long-lived enterprise API keys and cloud credentials granting access to frontier AI model endpoints (including Amazon Bedrock, Anthropic Claude, OpenAI, and Google Gemini). Wiz Research directly observed downstream enterprise exploitation in which stolen credentials powered over 2.5 million unauthorized model invocations on Amazon Bedrock across just two enterprise victim accounts, racking up over $100,000 in unbudgeted compute charges at list price within forty-eight hours. This investigation reveals the maturation of an industrialized cybercrime supply chain centered on "LLMJacking." Stolen enterprise AI credentials are no longer merely hoarded by isolated script kiddies; they are systematically funneled into commercial dark-market proxy pools ("LLM Brokers") such as llm-routing.com and xingjiabiapi.org, where unauthorized access to frontier models (such as Claude Opus 5.5, GPT-6 Astra, and Grok) is resold at steep discounts for cryptocurrency (USDT), or channeled into aggressive, high-volume model distillation pipelines to train rival domestic open-weight models. Black October establishes beyond doubt that static API keys embedded in cloud environments represent an unacceptable enterprise liability, underscoring the urgent imperative for ephemeral non-human identity (NHI) governance, real-time token rate-limiting, and AI Security Posture Management (AI-SPM). 03 The Convergence of Agent Swarms and LLMJacking

A critical technical insight highlighted by Fireworks AI, OpenCode, and Warp is the emergence of Agent Swarms as an offensive force multiplier. Rather than deploying traditional linear fuzzers or manual penetration testing scripts, threat actors deployed autonomous, LLM-orchestrated agent clusters. These swarms dynamically analyzed the build output, error logs, and memory dumps of compromised developer platforms to locate, classify, and test environment variables granting cloud infrastructure and AI model access. The speed of these autonomous swarms fundamentally breaks traditional incident response timelines. In multiple documented instances, the first unauthorized API call utilizing stolen enterprise keys occurred within 30 minutes of the initial compromise on the developer platform. By automating reconnaissance, privilege enumeration, and model capability probing, the attackers collapsed what was historically a multi-day lateral movement cycle into sub-hour machine execution. Forensic Deep Dive: The 2.5 Million Bedrock Invocation Trace ________________ Wiz Research obtained comprehensive telemetry from two enterprise victim organizations whose Amazon Web Services (AWS) Bedrock credentials were stolen via a compromised AI developer platform. Forensic analysis of these cases demonstrates the sophisticated operational tactics employed by the LLMJacking actors.

04 Initial Probing and Validation Loop

In both Case A and Case B, the threat actor initiated contact using an identical initial validation routine. Originating from a residential IP address, a lightweight Go client executed a single InvokeModel API call within a one-minute sweep across multiple stolen keys. The call specifically requested Anthropic's flagship Claude Fable 5.1 model. When that model was unavailable on the target account, the client immediately fell back to Claude Opus 5.5, which succeeded. Following this initial validation, the attacker placed the keys into a "keep-alive" verification loop. Over the subsequent four to seven days, the keys generated only 14 to 120 calls per day in lockstep, approximately one minute apart. This stealthy cadence verified that the victim enterprise had not yet noticed the breach or revoked the IAM credentials, while avoiding detection by rudimentary anomaly detection rules.

05 Case A: The Global Cross-Region Quota Flood

Four days after validation, the attackers unleashed a coordinated exploitation routine: * Catalog Probing: A rotating proxy pool executed a model catalog sweep across dozens of addresses, sending test prompts to Amazon Nova, DeepSeek, gpt-oss, GLM, Kimi, Grok, GPT-6 Astra, and Claude models to establish exact account permissions. * Quota Enumeration: A Python boto3 script running from a residential address enumerated all AWS Bedrock and EC2 service quotas. Twenty-two seconds after completing quota reconnaissance, high-volume bulk traffic commenced. * The Flood: Over a 30-hour window before security teams intervened, the actor executed approximately 800,000 Bedrock API calls, achieving a 90% success rate. The traffic originated from residential IPs before shifting to high-bandwidth Level 3 (AS10753) hosting infrastructure. Regional Routing Evasion: Because the compromised IAM policy permitted global. cross-region inference profiles, the actor dynamically routed calls across global AWS regions, diluting regional volume and keeping throttling rates below 6%. The traffic was overwhelmingly concentrated on expensive frontier reasoning models: Claude Opus variants comprised 76% of total calls (Opus 5 at 36%, Opus 5.5 at 22%, and Opus 4.8 at 10%).

06 Case B: Bypass of Regional Constraints and Reseller Ingestion

Case B involved an enterprise whose IAM policies were more tightly scoped, permitting inference only through us.* regional profiles: Initial Failure in Reseller Pool: Seven days post-compromise, the key surfaced in an automated reseller infrastructure. Thousands of calls initially failed because the reseller's automated rotation engine attempted to invoke global. endpoints. Adaptive Reconfiguration: The threat actor deployed an automated checker over a VPN exit node that parsed the error messages, recognized the policy restriction, and mapped the working us. model IDs. Two hours later, the exact same boto3 enumeration script observed in Case A probed the key's regional quotas. * The Flood: Over a compact 13-hour period, a single Level 3 hosting IP address launched 1.7 million Bedrock calls. More than 1 million calls succeeded, while the remainder hit regional account concurrency limits. Claude Opus 5.5, Sonnet 4.5, and Opus 5 accounted for over 75% of the consumed compute.

07 Token Economics and Financial Extraction

Analysis of the token payloads across both cases revealed a distinctive profile matching resold AI coding assistant traffic. Typical requests transmitted minimal uncached input tokens—indicating heavy utilization of prompt caching architectures characteristic of developer coding tools—while returning several hundred output tokens. A long tail of requests carried tens of thousands of input tokens, indicating diverse, concurrent end-users routing their workloads through the stolen keys. At standard commercial list prices, these two enterprise breaches generated over $100,000 in unbudgeted LLM inference costs in less than two days. 08 Darknet LLM Brokers: The "momo" and "Xingjiabi" Operations

Threat intelligence analysts identified specific threat actors and operational infrastructure brokering access to stolen API keys: * The "momo" Infrastructure (23.106.46.239): Active since 2025, this infrastructure originally operated services titled "ChatGPT Team Seat Redemption" and "ChatGPT Account Pool Management." In October 2026, it hosted an autonomous penetration testing console named ARTEX, which was directly implicated by Zeabur in their platform intrusion. The operator currently runs llm-routing.com, an active commercial clearinghouse advertising heavily discounted API access to frontier models, accepting payment exclusively in Tether (USDT). * The "Xingjiabi" Hub (38.246.114.118): Operating publicly via xingjiabiapi.org, this hub resells frontier AI access at a fraction of standard API pricing. Telemetry confirmed that servers resolving to s3.xingjiabiapi.org executed permission checks and quota enumerations against both Case A and Case B enterprise keys hours after bulk exploitation began.

09 The Model Distillation Threat

Beyond commercial token resale, multiple platform disclosures—specifically from OpenCode and CommandCode—highlighted unauthorized model distillation as a primary attack motivation. Distillation involves feeding massive datasets of synthetic prompts into a superior frontier reasoning model (such as Claude Opus 5.5 or GPT-6) and using the detailed outputs, chain-of-thought steps, and code solutions to train or fine-tune smaller, cheaper open-source models. Because frontier model terms of service strictly prohibit using their outputs to train competing models, rogue AI labs and commercial competitors cannot use legitimate enterprise accounts for large-scale distillation. By procuring stolen credentials via LLMJacking brokers, these actors siphon hundreds of millions of high-quality synthetic tokens on compromised enterprise budgets, insulating their own infrastructure from account suspensions and legal liability. Systemic Root Causes in the AI Infrastructure Stack ________________ The Black October disaster was made possible by systemic architectural failures across the enterprise AI engineering lifecycle: * Static Secrets in Environment Variables: Developers routinely embed raw API keys (e.g., AWS_SECRET_ACCESS_KEY, OPENAI_API_KEY, ANTHROPIC_API_KEY) into cloud configuration files, .env manifests, Docker containers, and CI/CD pipelines. Unlike human user identities, which are guarded by Multi-Factor Authentication (MFA), static AI tokens function as bearer tokens: anyone who possesses the string holds full operational authority. Unbounded Cloud IAM Policies: Cloud administrators routinely assign broad permissions (e.g., bedrock:InvokeModel across Resource: ) to development and application roles without restricting inference profiles to specific regions, VPC endpoints, or IP subnets. * Absence of Financial Circuit Breakers: Major cloud providers do not enforce hard, real-time dollar caps on AI model consumption by default. While budget alerting exists, it operates on asynchronous billing metrics with latency delays of 6 to 24 hours—far too slow to prevent machine-speed DoW attacks from racking up tens of thousands of dollars. * Third-Party SaaS Blind Spots: Enterprises increasingly connect their internal code repositories, documentation, and cloud environments to third-party AI developer platforms (such as Railway, Replit, or Warp) to accelerate developer velocity. When these external platforms suffer a breach, attackers immediately harvest the customer credentials stored in workspace databases, breaching the enterprise perimeter from the outside in. 10 Immediate Tactical Remediation (Next 72 Hours)

  • ▪Audit and Rotate All AI API Secrets: Immediately rotate all commercial API keys and cloud IAM access tokens associated with AI development platforms, developer laptops, and CI/CD environments. Treat any key active during October 2026 as potentially compromised.
  • ▪ Restrict AWS Bedrock and Cloud IAM Scopes: Replace wildcard () resource permissions with explicit model ARNs. Explicitly deny global.* cross-region inference profiles unless strictly required, restricting execution to local regional profiles (e.g., us-east-1).
  • ▪Bind API Access to Private VPC Endpoints: Configure IAM policies to enforce aws:sourceVpce conditions, ensuring that Bedrock API invocations can only originate from authenticated enterprise private cloud subnets, completely neutralizing attempts to invoke models from residential or hosting proxy pools.

11 Architectural Transformation: Ephemeral Non-Human Identity (NHI) (Days 30–60)

  • ▪Eliminate Static API Tokens: Mandate the use of short-lived, just-in-time (JIT) credentials brokered via enterprise identity control planes such as HashiCorp Vault 2.2 or AWS IAM Roles for Service Accounts (IRSA). Credentials should possess a maximum time-to-live (TTL) of 15 to 60 minutes.
  • ▪Deploy AI Security Posture Management (AI-SPM): Utilize Cloud-Native Application Protection Platforms (CNAPP) with native AI-SPM capabilities (such as Wiz, Palo Alto Networks Prisma, or Check Point) to continuously discover shadow AI pipelines, identify unencrypted API keys in code repositories, and map attack paths between SaaS platforms and cloud data lakes.

12 Runtime Defense & Financial Governance (Days 60–90)

  • ▪Implement Inline AI Gateways: Position dedicated AI runtime gateways (such as Fortinet FortiAIGate, Portkey, or Cloudflare AI Gateway) between client applications and model providers to enforce hard token budgets, rate limits, and automated loop termination.
  • ▪Automated Anomaly Detection & Kill Switches: Configure real-time CloudWatch and SIEM detection rules tracking sudden spikes in token velocity, off-hours invocation surges, or access to high-cost reasoning models. Integrate automated SOAR playbooks capable of instantly detaching IAM policies upon detection of credential abuse.
